# Display

What is drawn and when. The code: `main/display/display.c` picks the screen per state (`choose_screen()`) and
redraws; `main/screen/status_screen.c` draws the proper screen, `main/screen/debug_screen.c` the debug screen.
The panel itself and its quirks are in [hardware.md](hardware.md#e-paper-panel).

## Refresh policy

- 400x300, 1 bit. A partial refresh takes about 470 ms however many pixels change, a full clear about 500 ms.
- A frame identical to the one on the panel is not sent, so writes that change nothing on the screen cost no
  refresh.
- BOOT and SHUTDOWN clear the panel ([behaviour.md](behaviour.md#panel-on-each-wake)); in between every redraw is
  a partial refresh, with a full clear every `PARTIALS_BETWEEN_CLEARS` (50) partials against ghosting
  (`main/display/panel.c`).
- The Zigbee callbacks update the display model and mark it changed; the state loops wait with
  `display_wait_ms()`, which redraws when it has changed, so a burst of writes is drawn as it arrives. Writes
  during a refresh coalesce into the next one ([firmware.md](firmware.md#tasks-and-data-flow)).

## Fonts and icons

The accepted UI spec is the Claude doc "Bezárva? e-paper kijelző – design specifikáció" (mockups at actual
size). The layout constants in `status_screen.c` are measured from the mockups.

Fonts and icons are bitmaps generated by `tools/gen_bitmaps.py` into `main/screen/bitmaps.c` (committed, never
edited by hand; the `regen-bitmaps` skill):

- Inter (SIL OFL) at the mockups' sizes: line name 24 px bold, state 22 px semibold, "Minden OK" 32 px bold,
  device text 30 px bold, detail 18 px, pairing instructions 22 px; thresholded to 1 bit. Name and state fonts
  cover Latin-1 and Latin Extended-A, the fixed texts ASCII plus the Hungarian letters; a missing character is
  drawn as `?`.
- Material Design Icons 7.4.47 (the set HA uses): the [line icons](data-model.md#line-icons) at 30 px,
  `check-circle` at 152 px, the device icons at 150 px (`gesture-tap-hold` at 120 px) and the stale badge's
  `sync` at 24 px.

The mockups' text is about 4 % wider than this rendering (kerning, browser rasterising); positions and heights
match.

## House screens

No header; the content fills the screen.

- **Problems**: up to 6 rows of 50 px from the top, each the line icon, the bold name and the state
  right-aligned, dotted separators between rows; unused rows stay blank. The name is cut with "…" to leave room
  for the state (a state wider than 180 px is cut as well). More than 6 active lines: 5 rows and "további N"
  with the dots icon ([layout rule](data-model.md#layout-rule)).
- **No active lines**: "Minden OK": a large solid `check-circle`, bold "Minden OK", and two fixed lines ("Ajtók,
  ablakok zárva", "Készülékek kikapcsolva"). The only large black shape on any screen.
- **Stale view** ([staleness flag](data-model.md#staleness-flag)): a badge drawn over the content, white `sync`
  arrows on a black disc (34 px) in a white ring (4.5 px). Its right edge lines up with the states and
  separators, and it is centred on the first row's icon, so it may cover the end of the first state; nothing
  moves.

## Device screens

No header; a large outline icon, centred, one bold line. "Párosítás" adds two instruction lines with a smaller
icon.

| Screen | Icon | Shown |
|---|---|---|
| Hálózatkeresés | access-point | PAIRING, ERASE_NETWORK (pairing follows the restart) |
| Csatlakozás | access-point | INTERVIEW |
| Szinkronizálás | sync | REJOIN / ACTIVE with no view stored yet, while dataset entries arrive (until their commit), and after an out-of-sync view |
| Párosítás | gesture-tap-hold (120 px) | UNPAIRED, also after a pairing attempt timed out, and to sleep with after an unpaired wake; two instruction lines under the title ("Engedélyezd a csatlakozást", "Nyomd a gombot 3 mp-ig", 22 px) |
| Csatlakozási hiba | alert-outline | to sleep with, after a rejoin timeout |
| Akkumulátor lemerült | battery-outline | to sleep with in LOW_BATTERY, until USB power |
| Ismeretlen hiba | alert-outline | to sleep with, when the Zigbee stack did not start |

Otherwise the house screen: BOOT draws the stored view (blank when there is none), SHUTDOWN the stored view
(Szinkronizálás when there is none). A failure screen stays until the next wake.

## Debug screen

For RnD, built with `idf.py -DDEBUG_SCREEN=1 build` instead of the proper screen (macro `RENDER_DEBUG_SCREEN`;
`=0` switches back, CMake caches the value). u8g2 font `t0_16b_te` (Terminus Bold, 49 columns x 16 px rows; 1 px
fonts are too faint on this panel), the same in every state; rows show the raw `II|name|state` text:

```
ACTIVE          w412 37.2s          state, wake counter, uptime
DS 499181 n=4  VIEW 969F82          stored dataset (hash, entries) and shown view id
age 3s / 8s FRESH  2 lines         age of the last view received, its validity, the staleness flag,
                                    active line count ("OUT OF SYNC" if the last view was); age "-" = unknown
1 02|Teraszajtó|nyitva              ... the shown rows (up to 6; "ALL OK" for none)
36.9 V 969F82 b=00000005 OK         last received writes, newest first, uptime stamp:
36.7 D 499181 n=4 OK                  V = view (OK, TIME, OOS ds=<hash>), E = ds_entry index and text,
36.5 E 03 0D|Nappali lámpa|be         D = ds_commit (OK, REJ idx=<first missing>, BAD N)
```

The age ticks, so the debug screen refreshes about once a second while awake. Rows longer than 49 characters are
cut off. Outgoing reports are not shown. A dataset sync of 32 entries scrolls the receive log; only the last few
are visible.

## Checking against the mockups

`idf.py -DSCREEN_DUMP=1 build` (`=0` to switch off) prints every frame sent to the panel on the console, and at
boot every screen once with the mockups' content and a few edge cases (malformed line, unknown icon id, long
name and state, empty state), without drawing them (`main/display/frame_dump.c`). `tools/fb_dump.py --reset`
resets the board and saves the frames as PNGs. It costs about 2 s at boot and a few hundred ms per frame (the
console is slow, and the Zigbee task logs through it too), so it is off in normal builds. Last checked
2026-10-31: all ten mockups reproduced, the differences being glyph hinting.
