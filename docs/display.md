# Display

How the screens are built and when each is shown. What they look like and why is the
[UI spec](uispec/ui-spec.md), with the accepted mockups. The code: `main/app/screen_content.c` decides from the application state which screen to show
(`screen_content_of()`), `main/display/display.c` redraws, `main/screen/status_screen.c` draws the proper screen and
`main/screen/debug_screen.c` the debug screen.
The panel itself and its quirks are in [hardware.md](hardware.md#e-paper-panel).

## Refresh policy

- 400x300, 1 bit. Refresh and clear times: [hardware.md](hardware.md#e-paper-panel).
- A frame identical to the one on the panel is not sent, so writes that change nothing on the screen cost no
  refresh.
- BOOT and SHUTDOWN clear the panel ([behaviour.md](behaviour.md#panel-on-each-wake)); in between every redraw is
  a partial refresh, with a full clear every `PARTIALS_BETWEEN_CLEARS` (50) partials against ghosting
  (`main/panel/panel.c`).
- The Zigbee callbacks update the application state; the state loops wait with `display_wait_ms()`, which
  redraws when the screen would change, so a burst of writes is drawn as it arrives. Writes during a refresh
  coalesce into the next one ([firmware.md](firmware.md#tasks-and-data-flow)).

## Fonts and icons

The layout constants in `status_screen.c` are measured from the [mockups](uispec/ui-spec.md).

Fonts and icons are bitmaps generated by `tools/gen_bitmaps.py` into `main/screen/bitmaps.c` (committed, never
edited by hand; the `regen-bitmaps` skill):

- Inter (SIL OFL) at the mockups' sizes: line name 24 px bold, state 22 px semibold, *All OK* title 32 px bold,
  device text 30 px bold, detail 18 px, pairing instructions 22 px; thresholded to 1 bit. Name and state fonts
  cover Latin-1 and Latin Extended-A, the fixed texts ASCII plus the Hungarian letters; a missing character is
  drawn as `?`.
- Material Design Icons 7.4.47 (the set HA uses): the [line icons](data-model.md#line-icons) at 30 px,
  `check-circle` at 152 px, the device icons at 150 px (`gesture-tap-hold` at 120 px) and the stale badge's
  `sync` at 24 px.

The mockups' text is about 4 % wider than this rendering (kerning, browser rasterising); positions and heights
match. The sizes and positions were fitted by measuring the mockups before the [UI spec](uispec/ui-spec.md#layout-and-type)
recorded the design values, so they differ from it slightly: the text weights are a step heavier (name 700 for
600, state 600 for 400, detail and instruction lines 500 for 400), the right edge is 387 for 388, the
unpaired instruction baselines are 217 / 249 for 218 / 250, `check-circle` is 152 px for 150, and the stale
badge's ring is 4.5 px wide for 4.

## House screens

The look is in the [UI spec](uispec/ui-spec.md#house-screens); as built:

- **Problems**: 6 rows of 50 px from the top. The name is cut with "…" to leave room for the state (a state wider
  than 180 px is cut as well). More than 6 active lines: 5 rows and "N more" (`további N`), as the
  [UI spec](uispec/ui-spec.md#problems) says. The device stores every active line
  ([data-model.md](data-model.md#view)), so the row count is the screen's alone (`main/screen/status_screen.c`).
- **All OK** when no line is active.
- **Stale badge** when the [staleness flag](data-model.md#staleness-flag) is set: the `sync` arrows on a 34 px
  black disc in a 4.5 px white ring.

## Device screens

The look is in the [UI spec](uispec/ui-spec.md#device-screens); the *Pairing* screen's icon is 120 px, its instruction
lines 22 px. When each is shown (`screen_kind_t` in `main/app/screen_content.h`):

| Screen | Shown |
|---|---|
| Network search | PAIRING, ERASE_NETWORK (pairing follows the restart) |
| Connecting | INTERVIEW |
| Synchronizing | REJOIN / ACTIVE with no view stored yet, while dataset entries arrive (until their commit), and after an out-of-sync view |
| Pairing | UNPAIRED, also after a pairing attempt timed out, and to sleep with after an unpaired wake |
| Join failed | to sleep with, after a rejoin timeout |
| Battery dead | to sleep with after a low battery: in LOW_BATTERY until USB power, or in SLEEP when the report was not confirmed ([behaviour.md](behaviour.md#low-battery)) |
| Unknown error | to sleep with, when the Zigbee stack did not start |

Otherwise the house screen: BOOT draws the stored view (blank when there is none), SHUTDOWN the stored view
(*Synchronizing* when there is none). A failure screen stays until the next wake.

## Debug screen

For RnD, built with `idf.py -DDEBUG_SCREEN=1 build` instead of the proper screen (macro `RENDER_DEBUG_SCREEN`;
`=0` switches back, CMake caches the value). u8g2 font `t0_16b_te` (Terminus Bold, 49 columns x 16 px rows; 1 px
fonts are too faint on this panel), the same in every state; rows show the raw `II|name|state` text:

```
ACTIVE    3.86V w412 37.2s          state; battery (with USB or LOW), wake counter, uptime
DS 499181 n=4  VIEW 969F82          stored dataset (hash, entries) and shown view id
age 3s / 8s FRESH  2 lines         age of the last view received, its validity, the staleness flag,
                                    active line count ("OUT OF SYNC" if the last view was); age "-" = unknown
1 02|Teraszajtó|nyitva              ... the shown lines (up to 6; with more, 5 and "+N more"; "ALL OK" for none)
36.9 V 969F82 b=00000005 OK         last received writes, newest first, uptime stamp:
36.7 D 499181 n=4 OK                  V = view (OK, TIME, OOS ds=<hash>, PART m=<attributes>),
36.5 E 03.0 0D|Nappali lámpa|be       E = ds_entry line.part (+ = more parts follow) and text,
                                      D = ds_commit (OK, SAME, REJ idx=<first missing>, BAD N)
```

The age ticks, so the debug screen refreshes about once a second while awake. Rows longer than 49 characters are
cut off. Outgoing reports are not shown. A dataset sync of 32 entries scrolls the receive log; only the last few
are visible.

## Checking against the mockups

`idf.py -DSCREEN_DUMP=1 build` (`=0` to switch off) prints every frame sent to the panel on the console, and at
boot every screen once with the mockups' content and a few edge cases (malformed line, unknown icon id, long
name and state, empty state), without drawing them (`main/screen/sample_screens.c`). `tools/fb_dump.py --reset`
resets the board and saves the frames as PNGs. It costs about 2 s at boot and a few hundred ms per frame (the
console is slow, and the Zigbee task logs through it too), so it is off in normal builds. Last checked
2026-10-31: the ten mockups of the time reproduced, the differences being glyph hinting. The mockups are in
[mockups/](uispec/mockups/) since 2026-11-06.
