# Firmware

ESP-IDF v6.1, C, CMake. Coding conventions (prefixes, includes, log tags) are in [CLAUDE.md](../CLAUDE.md).

## Source layout

Every file under `main/` has one purpose and is named after it.

| Path | Purpose |
|---|---|
| `main.c` | start-up order: sets up the parts, then runs the state machine |
| `state_machine.c` | the states and timeouts ([behaviour.md](behaviour.md)) |
| `console.c` | USB console commands (`bat`, `usb`, `vbat`) |
| `persistent_store.c` | NVS keys and access ([Persistent state](#persistent-state)) |
| `board/board.c` | pin map (`board.h`), RF switch |
| `board/inputs.c` | PIR and pair button: polling, debounce, occupancy hold |
| `board/battery.c` | battery voltage (measured or overridden), simulated USB power, low-battery latch |
| `board/battery_sense.c` | battery measurement on D2 (ADC) |
| `board/sleep.c` | deep sleep (or the simulated sleep) |
| `board/wake_reason.c` | the wake cause, logged at boot |
| `display/display.c` | screen per state (`choose_screen()`), redraw, `display_wait_ms()` |
| `display/display_model.c` | the mutex-guarded dataset, shown view and received writes; the Zigbee callbacks |
| `display/view_freshness.c` | staleness deadline in RTC memory ([data-model.md](data-model.md#staleness-flag)) |
| `display/panel.c` | refresh / clear policy and the `panel:` log |
| `display/frame_dump.c` | `SCREEN_DUMP` output |
| `display/framebuffer.c` | the 1-bit framebuffer (also u8g2's draw target) |
| `display/epaper.c` | SSD1683 driver ([hardware.md](hardware.md#e-paper-panel)) |
| `screen/render.c` | picks the proper or the debug screen |
| `screen/status_screen.c` | the proper screen ([display.md](display.md)) |
| `screen/debug_screen.c` | the RnD debug screen |
| `screen/view_layout.c` | the shown rows of a view |
| `screen/bitmap_text.c` | Inter text and icons from the bitmaps |
| `screen/bitmaps.c` | generated by `tools/gen_bitmaps.py`, never edited by hand |
| `zigbee/zigbee.c` | stack, network, public API |
| `zigbee/zigbee_device.c` | endpoint and clusters ([zigbee.md](zigbee.md#endpoint-and-clusters)) |
| `zigbee/zigbee_display_input.c` | view and dataset writes ([zigbee.md](zigbee.md#input-ha-to-device)) |
| `zigbee/zigbee_reports.c` | reports to the coordinator ([zigbee.md](zigbee.md#state-device-to-ha)) |
| `zigbee/zigbee_internal.h` | shared between the `zigbee/` files only |
| `util/utf8.c`, `util/hex.h`, `util/elapsed_time.h` | helpers |

Other folders: `tools/` (bitmap and mockup generators, serial console, framebuffer dump, Zigbee bench test,
docs checker), `z2m/` (the
Zigbee2MQTT converter), `ha/` (the Home Assistant sources).

Dependencies: the Zigbee libraries (`espressif__esp-zigbee-lib`, `esp-zboss-lib`) and u8g2 (upstream git,
pinned to a commit), all in `main/idf_component.yml`. u8g2 is used only for the debug screen's font and text,
drawn through a callback into the framebuffer, never for the panel. The top-level `CMakeLists.txt` sets `MINIMAL_BUILD ON`, so a
new component dependency must be declared in `main/CMakeLists.txt` (`PRIV_REQUIRES`).

`sdkconfig` is generated and git-ignored; `sdkconfig.defaults` (from `idf.py save-defconfig`: target,
USB-Serial-JTAG primary console, Zigbee end device) holds the non-default settings, so rerun `save-defconfig`
after changing `menuconfig`. `sdkconfig.ci` holds CI-only overrides (currently empty). `.devcontainer/` defines an
ESP-IDF QEMU container; `.clangd` strips `-f*` / `-m*` flags so clangd copes with the RISC-V GCC flags in
`compile_commands.json`.

## Tasks and data flow

- `app_main()` sets up the parts in order, then runs the state machine (`state_machine_run()`) in the main task.
- `input_task` polls and debounces D0 and D1 (level based); `console_task` reads the console commands.
- The Zigbee task runs the stack. Its callbacks update the mutex-guarded display model
  (`display/display_model.c`) and mark it changed (`display_model_mark_changed()`). A view write is applied by
  `apply_view()` after the whole frame has been processed.
- The state loops wait with `display_wait_ms()`, which redraws when the model has changed or the staleness flag
  flipped, so a burst of writes is drawn as it arrives; writes during a refresh (about 0.5 s) coalesce into the
  next one.

## Persistent state

A wake is a reset, so what must survive sleep is in NVS, namespace `greenlight` (`persistent_store.h`; the key
strings address state on devices, never change them). The Zigbee stack keeps the network in the same partition.

| Key | Content |
|---|---|
| `pair_now` | start pairing right after the next boot (set by ERASE_NETWORK) |
| `wake_n` | the wake counter |
| `ds` | the dataset |
| `view` | the shown view with its laid-out rows |
| `sim_mv`, `sim_usb` | the battery voltage override (0 = measured) and the simulated USB power |
| `bat_low` | the low-battery latch |

The staleness deadline lives in RTC memory (`RTC_NOINIT_ATTR`): it survives a restart and deep sleep, and is
cleared after a power-on.

To get a factory-new device, erase NVS: `python -m esptool --chip esp32c6 -p COM5 erase-region 0x9000 0x6000`.

## Build switches

CMake caches them; pass `=0` to switch back.

| Switch | Effect |
|---|---|
| `-DDEBUG_SCREEN=1` | the RnD debug screen instead of the proper screen ([display.md](display.md#debug-screen)) |
| `-DSCREEN_DUMP=1` | print every frame on the console for `tools/fb_dump.py` ([display.md](display.md#checking-against-the-mockups)) |
| `-DSLEEP_TIMER_S=N` | a timer also ends deep sleep after N s (bench tests) |
| `-DSIM_SLEEP=1` | simulated sleep: wait for D0 or D1, then `esp_restart()`. USB, the log, the console and resets over USB keep working, so use it for autonomous testing. |

## Simulated parts

- **The battery voltage** is measured on D2 at boot, before the radio and the panel start (logged as `battery
  sense: pin ... mV, vbat ... mV`), and again, unlogged, at every mid-wake battery check
  ([behaviour.md](behaviour.md#low-battery)). The `vbat` console command measures and logs. On USB without a cell the reading means nothing (the charger's output is not a battery
  voltage), and without the USB sense the device cannot tell.
- **The voltage override and USB power** are set over the USB-Serial-JTAG console (the primary console, so it
  takes input): `bat <mV>` (2500-4500; `bat 0` = measured again), `usb 0|1`; `bat` / `usb` alone print them.
  They are kept in NVS (`sim_mv`, default 0 = measured; `sim_usb`, default 0 = on battery), so they survive the
  sleep, a power cycle and a reflash. Usage with `tools/console.py`: the `bench-test` skill.
- **LOW_BATTERY** waits for `usb 1`, then calls `esp_restart()`: the real USB sense is not wired,
  and the simulated `usb 1` cannot reach a sleeping chip.
